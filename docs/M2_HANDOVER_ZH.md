# M2 交接说明 —— 我们做了什么、为什么这么做、结果如何

给队友看的。假设你没跟过这个过程,从零讲起。看完你应该能自己跑通,并且知道 M3 该往哪走。

## 0. 五分钟看懂

我们基于的论文叫 **StealthDiffusion**(ACM MM 2024)。它做的事是:把一张 AI 生成的图改一改,让「AI 图检测器」误以为它是真实照片,同时人眼看不出区别。我们是 Theme 1 的 **Dark(攻击方)**,任务是**把这个攻击做得更强**。

我们做了五处改动,拿它们组合出四个版本对比。**主要结论有三条,其中两条是坏消息 —— 但坏消息才是我们这次最值钱的东西。**

1. **好消息**:把"用一个检测器指导攻击"换成"用三个检测器的平均",成功率从 0.77 提到 0.98,而且在一个**从头到尾没参与过训练的检测器**上也涨了。
2. **坏消息一**:这个攻击**扛不住后处理**。图片存一次 JPEG,一半的攻击效果就没了;缩放一次,论文原版只剩两成。而论文里所有数字都是在无损 PNG 上测的。
3. **坏消息二**:用 AUC 一看,**四个检测器其实一个都没真被骗**。我们的图被推得"比真照片还像真照片",防守方翻一下阈值就能全抓。

## 1. 这篇论文在干什么

任务全称 **AIGC-S**(AI-Generated Content Stealth,AI 生成内容隐身)。

有一类模型叫「AI 图检测器」,输入一张图,输出"这是 AI 生成的"还是"这是真实照片"。StealthDiffusion 要骗过它们。

流程分三步:

| 步骤 | 做什么 | 通俗讲 |
|---|---|---|
| **① PGD** | 在像素上加一层微小扰动(强度 4/255) | 传统对抗攻击,直接改像素 |
| **② LAO** | 把图编码进 Stable Diffusion 的潜空间,跑一小段扩散,在潜空间里优化 | 论文的**核心卖点**,在"语义空间"里改而不是在像素上改 |
| **③ Control-VAE** | 用一个特制的解码器把潜变量解码回图片 | 这个解码器被专门训练过,用来抹掉 SD 留下的频域指纹 |

**LAO = Latent Adversarial Optimisation(潜空间对抗优化)**,是论文自称的主要贡献。记住这个词,后面有个重要发现跟它有关。

## 2. 术语表(看结果之前必须先懂)

### 2.1 四个检测器:E / R / D / S

论文自带四个检测器,我们全程用它们的官方权重,一个都没重训:

| 代号 | 全名 | 架构类型 | 权重文件 |
|---|---|---|---|
| **E** | EfficientNet-B0 | CNN(卷积网络) | `efficientnet-b0.pth` |
| **R** | ResNet-50 | CNN | `resnet50.pth` |
| **D** | DeiT-Base | Transformer | `deit.pth` |
| **S** | Swin-T | Transformer | `swin-t.pth` |

**为什么要分 CNN 和 Transformer**:后面我们踩的那个 bug,只影响 CNN(E、R),不影响 Transformer(D、S)。正是这个差异让我们定位到了问题。

### 2.2 标签约定:**0 = AI,1 = 真实**

这个很反直觉,但论文代码就是这么定的,我们保持一致。所以:

- 检测器输出 `pred = 0` → 它认为这是 AI 图 → **攻击失败**
- 检测器输出 `pred = 1` → 它认为这是真照片 → **攻击成功**

日志里打印的 `E:real` 意思是「E 被骗过去了」,`E:AI` 意思是「E 识破了」。

### 2.3 margin(间隔)

`margin = logit_real − logit_AI`

简单说就是"检测器觉得这图有多像真的"。

- margin > 0 → 判定为真照片
- margin < 0 → 判定为 AI
- 数值越大,越确信

举例,我们在 dev 集上测的基线:

| 检测器 | 真照片的 margin | AI 图的 margin |
|---|---|---|
| E | +16.31 | −4.00 |
| R | +7.98 | −5.59 |
| D | +4.90 | −6.43 |
| S | +9.99 | −5.11 |

**这张表的用法**:AI 图的 margin 就是"攻击要走多远"。E 只要涨 4.0 就能翻过 0,D 要涨 6.4。所以 **E 最好骗,D 最难骗**。

### 2.4 白盒 / 黑盒 / 迁移

- **白盒**:攻击的时候用了这个检测器来算梯度 → 相当于开卷考试
- **黑盒 / 迁移**:攻击的时候完全没用过它 → 相当于闭卷

**S 在我们所有四个版本里都没进过损失函数**,所以 S 上的成绩才是真本事。这是我们实验设计里最关键的一条。

### 2.5 条件 ASR(conditional ASR)—— 我们最主要的指标

ASR = Attack Success Rate,攻击成功率。

但"成功率"的分母是什么?这里有个坑:**有些 AI 图,检测器本来就认不出来**。如果把这些也算进成功,等于白捡分。

所以我们用**条件 ASR**:

> 分母 = 攻击**之前**就被这个检测器正确抓住的图
> 分子 = 这些图里,攻击**之后**骗过去的

**论文没有说它的 ASR 分母是什么。** 我们每次都把分母打出来。

我们数据上的分母(20 张 SD 图里,各检测器攻击前抓住了几张):

```
E: 14/20     R: 12/20     D: 19/20     S: 12/20
```

### 2.6 真实图假阳性率(real FPR)

检测器把**真照片**误判成 AI 的比例。

**为什么必须报这个**:如果一个检测器把所有图都判成 AI,那它的 ASR 会是 0 —— 看起来"完全抵抗了攻击",其实它只是坏了。没有 FPR 这一列,我们会得出完全错误的结论。后面第 6 节有个真实案例。

### 2.7 AUC(real vs attacked)

前面几个指标看的都是**判决**(判成 AI 还是真)。AUC 看的是**排序**:如果检测器调整一下阈值,还能不能把攻击后的图和真照片分开?

- AUC = 0.5 → 完全分不开,**攻击真正成功**
- AUC = 1.0 → 完全分得开,攻击没用
- **AUC = 0.0 → 也是完全分得开,只是方向反了**

最后那条是本次最重要的发现,第 7 节展开。

## 3. 我们改了什么,以及为什么会想到这么改

我们先找论文的弱点,再针对性地改。不是随便加功能。

### 弱点 (a):迁移性不稳

**证据**:论文自己的 Table 2,同一个方法迁移到 UniDetection 上,ASR 分别是 46.4% / 61.1% / 18.6% / 27.8% —— 只是换了指导攻击的那个检测器,结果差了三倍多。

**为什么会这样**:攻击只针对**一个**检测器优化,学到的是那一个模型的私有特征,换个模型就不灵了。

**我们的改法 ——`--surrogates E,R,D`**
PGD 阶段和 LAO 损失都改成**三个检测器的平均**。逼攻击去找它们共有的弱点,而不是某一个的私有怪癖。

### 弱点 (b):优化的图和保存的图不是同一张

**证据**:读官方代码 `diff_latent_attack.py` 发现的。优化循环里算损失用的是**普通 VAE** 解码(缩放系数 0.18215),但最后存到硬盘的图是 **Control-VAE** 解码的(缩放系数 0.1825)。

**为什么是问题**:攻击可能在"它优化的那张图"上成功了,但在"实际输出的那张图"上失败。

**我们的改法 ——`--decode_path final`**
让损失直接算在**最终输出的那条解码路径**上(同一个解码器、同一个缩放系数、同一套控制特征)。梯度仍然只传到潜变量,Control-VAE 本身保持冻结。

### 弱点 (c):完全没测过后处理

**证据**:论文所有数字都在无损 224×224 PNG 上。但现实里图片在被检测之前一定会被压缩、缩放。

另外官方代码**算了 LPIPS 但从来没放进损失函数**,等于白算。

**我们的三个改法:**

**`--loss margin`** —— 把目标从 `−CE` 换成 `relu(kappa − margin)`。
- 原来的 `−CE` **没有下界**,优化器会一直推一直推,永远停不下来。
- 新的目标是"推过 0 再多留 kappa 的余量就停"。留余量是为了扛住后续的压缩。
- **kappa = 3.0 不是拍脑袋定的**:D 给真照片的 margin 才 4.90,所以要求攻击后的图达到 +3,等于是"在 D 眼里跟真照片差不多可信"。

**`--lpips_weight 1.0`** —— 把 LPIPS(感知距离)真正加进损失,让画质被约束住,而不是只在旁边看着。

**`--di_prob 0.5`** —— 输入多样性(Input Diversity)。有 50% 概率把解码后的图随机缩放到 90~100% 再补零回 224,然后才给检测器看。这个操作可微,梯度能正常传。目的是让攻击不要过拟合到某一个固定尺寸。

## 4. 四个版本为什么这样设计

这是**消融实验**:一次只动一个东西,才知道是哪个东西起了作用。

| 版本 | 损失里用哪些检测器 | 解码路径 | 目标函数 | 额外项 | 它回答什么问题 |
|---|---|---|---|---|---|
| **B00** | E | 普通 VAE | 交叉熵 | 无 | 官方原版,我们的基线 |
| **B10** | E | **最终 Control-VAE** | 交叉熵 | 无 | 单独看弱点 (b) 值不值得修 |
| **ENS** | **E+R+D** | 普通 VAE | 交叉熵 | 无 | 单独看集成有没有用 |
| **FULL** | E+R+D | 最终 Control-VAE | **margin** | **LPIPS + DI** | 全开 |

**B00 → B10 只差解码路径,B00 → ENS 只差检测器数量。** 这样差异才能归因。

**S 在四个版本里都没进损失。** 所以 S 那一列是唯一干净的迁移测试。

其他所有超参都锁死不动(扩散步数、学习率、迭代次数、PGD 强度、分辨率、随机种子),否则版本之间没法比。

## 5. 怎么跑

环境:conda env `fit5230m2`(Python 3.10, torch 2.2.2),在 Mac 上用 MPS 跑,**不需要 GPU**。

```bash
conda activate fit5230m2
cd ~/StealthDiffusion              # 官方仓库,已把我们的 m2_*.py 复制进去

bash run_local_mac.sh check        # 检查 6 个权重文件在不在
bash run_local_mac.sh data         # 造数据集 + 打印检测器基线表
N_ATTACK=20 bash run_local_mac.sh attack    # 跑四个版本,约 16 分钟
bash run_local_mac.sh eval         # 评测(含 JPEG / 缩放)
bash run_local_mac.sh challenge    # 生成给别队的盲测包
```

**几个有用的参数:**

| 参数 | 含义 | 默认 |
|---|---|---|
| `N_ATTACK` | 攻击几张图 | 6 |
| `--resume` | 跳过已经跑完的图,可以随时中断续跑 | 脚本里已开 |
| `--device` | `auto` / `cuda` / `mps` / `cpu` | auto |
| `--max_images` | 同 N_ATTACK | 0(全部) |

**单独调试某一个版本:**
```bash
python m2_stealth.py --images_root data/gen/test --save_dir results/试验1 \
  --surrogates E,R,D --decode_path final --loss margin --kappa 3.0 \
  --lpips_weight 1.0 --di_prob 0.5 --device mps --max_images 5
```

**看某个 run 到底发生了什么(不用重跑,只读已保存的记录):**
```bash
python m2_diag.py --runs B00=results/B00 ENS=results/ENS
```
它会把攻击拆成四个阶段(原图 → PGD 后 → 普通 VAE 解码后 → Control-VAE 解码后),告诉你是哪一步起的作用、哪一步把成果丢掉了。**这个脚本是我们定位 bug 的关键工具,以后遇到怪结果先跑它。**

## 6. 结果

数据:20 张真照片(Imagenette)+ 20 张 SD 2.1-base 生成图,224×224。

### 6.1 无损 PNG 上的条件 ASR(越高越好)

`*` 表示这个检测器参与了攻击损失(白盒)

| 版本 | E (n=14) | R (n=12) | D (n=19) | **S (n=12,黑盒)** | 平均 |
|---|---|---|---|---|---|
| B00(官方) | 1.00* | 0.67 | 0.58 | 0.83 | 0.77 |
| B10 | 1.00* | 0.67 | 0.58 | 0.83 | 0.77 |
| **ENS** | 1.00* | **1.00*** | **1.00*** | **0.92** | **0.98** |
| **FULL** | 1.00* | **1.00*** | **1.00*** | **0.92** | **0.98** |

这一列的真实图假阳性率全是 0.00,所以数字是可信的。

**怎么读:**
- 集成(ENS)把 R 从 0.67 拉到 1.00,D 从 0.58 拉到 1.00 —— 但这两个变成白盒了,涨是应该的。
- **真正有意义的是 S:0.83 → 0.92,而 S 从头到尾没进过损失。** 这才是迁移性的真实提升,正好是我们要打的弱点 (a)。
- **B10 一点用都没有。** 判决和 B00 完全一样。弱点 (b) 在数值上存在,但不足以改变任何一个判决。**这是个阴性结果,我们照实写进帖子了。**

### 6.2 后处理之后(这是最重要的一张表)

对每个条件下**仍然正常工作**的检测器取平均:

| 版本 | 无损 PNG | JPEG 75 | 0.5× 缩放 |
|---|---|---|---|
| B00(官方) | 0.77 | 0.42 (−45%) | 0.17 (−78%) |
| B10 | 0.77 | 0.38 (−51%) | 0.17 (−78%) |
| **ENS** | **0.98** | 0.56 (−43%) | 0.46 (−53%) |
| **FULL** | **0.98** | 0.54 (−45%) | 0.46 (−53%) |

**论文里每一个数字都是第一列。** 图片存一次 JPEG,一半的攻击就没了;缩放一次,官方版本只剩两成。这是论文最大的空白,现在有数了。

**意外收获**:集成不只提高了无损那一列,**它同时提高了鲁棒性** —— 缩放之后 B00 只剩 0.17,我们的有 0.46,差了快 3 倍。这个我们没设计过。

### 6.3 为什么有些检测器要从平均里剔掉

| 条件 | 检测器 | 真照片假阳性率 | 说明 |
|---|---|---|---|
| JPEG 75 | **S** | **0.70** | 把 70% 的真照片也判成 AI |
| 0.5× 缩放 | **E** | **0.55** | 把 55% 的真照片判成 AI,而且 20/20 张生成图全判成 AI |

**S 在 JPEG 下 ASR 只有 0.11,看起来"扛住了攻击"。其实它是坏了** —— 它把什么都判成 AI,包括真照片。把这个算成"检测器胜利"就是错的。

这就是为什么必须报 FPR。少了这一列,我们会写出完全错误的结论。

### 6.4 画质和耗时

| 版本 | PSNR | SSIM | LPIPS | L∞ | 秒/张 |
|---|---|---|---|---|---|
| B00 | 34.02 | 0.907 | 0.164 | 0.183 | 10.9 |
| B10 | 32.77 | 0.906 | 0.165 | 0.189 | 10.5 |
| ENS | 33.95 | 0.907 | 0.162 | 0.188 | 11.2 |
| FULL | 33.51 | 0.908 | **0.156** | 0.189 | 11.9 |

FULL 攻击最强,LPIPS 反而最低(画质最好)—— 这正是加 LPIPS 项的目的。

**注意 L∞ ≈ 0.188,也就是 48/255,是名义预算 4/255 的 12 倍。** 不是 bug:PGD 之后图还要过 DDIM 反演、两步扩散、第二个解码器,这些都没有范数约束。所以我们报**实测失真**,不宣称"我们控制在 4/255 以内"。论文在这点上讲得不够清楚。

## 7. 最重要的发现:AUC 说明其实没人被骗

前面看的都是**判决**。现在看**排序**。

无损 PNG 上,真照片 vs 攻击后的图的 AUC:

| 检测器 | B00 | B10 | ENS | FULL |
|---|---|---|---|---|
| E | **0.00** | **0.00** | **0.00** | **0.00** |
| R | 0.80 | 0.81 | **0.00** | **0.00** |
| D | 0.93 | 0.93 | 0.17 | 0.16 |
| S | 0.98 | 0.99 | **0.96** | **0.96** |

**AUC = 0.00 不是"分不开",是"完全分得开,但方向反了"。**

我们的攻击图被推得**比真照片还像真照片** —— E 给攻击图的平均 margin 是 **+153**,真照片根本到不了这个数。防守方只要加一条规则「太自信地像真的,就是假的」,100% 全抓。

**S 是另一种失败**:ASR 已经 0.92 了,AUC 还是 **0.96** —— 攻击翻转了 S 的判决,但**完全没有扰动它的排序**。重新校准一下阈值,S 一张都不会漏。

所以对我们自己最诚实的评价是:

> **ENS 在无损 PNG 上拿到 0.98 的平均条件 ASR,但四个检测器没有一个是真被骗了。三个被推过头推反了,一个纹丝不动。**

**根因是交叉熵没有下界** —— 永远有更多损失可以降,优化器就永不停止。这正是 `--loss margin` 要修的。但它只管住了 LAO,**PGD 阶段结束时 margin 已经是 +97 了**,LAO 接手时木已成舟,而 PGD 完全没有约束。

**这条直接变成了 M3 的第一项任务。**

## 8. 我们踩的坑(值得记住的教训)

第一次用真权重跑出来的结果是不可能的:**把 E 加进损失函数,攻击在 E 上反而从 6/6 掉到 0/6。**

**是怎么发现的**:诊断脚本里有一列是"原图上的预测"。原图没被攻击过,这个预测**不可能**随着我们选哪些 surrogate 而变化。但它变了 —— 而且只有 E 和 R 变,D 和 S 一模一样。E、R 是 CNN(有 BatchNorm),D、S 是 Transformer(只有 LayerNorm)。

**原因**:我们写的 `Ensemble` 包装类是个新建的 `nn.Module`,默认处于 **training 模式**。`torchattacks` 会记录 `model.training`、攻击时切到 eval、**返回时恢复原状** —— 于是把里面三个检测器全塞回了 training 模式。之后 batch size=1 的 BatchNorm 改用单张图的统计量,还不停覆写 running stats,E 和 R 就此报废。

**修法**(三重保险):
1. `Ensemble.__init__` 里强制 `self.eval()`
2. 每次 PGD 返回后强制把所有检测器拉回 eval
3. `predict()` 里加 `assert not det.training` —— **以后再犯就直接崩,不会再静默污染数据**

`tests/bn_mode_repro.py` 用 40 行复现了这个机制,不依赖 StealthDiffusion,可以单独跑。

**教训**:数字看起来合理不代表它是对的。**能在跨配置之间保持不变的量(比如 clean 预测),是最好的一致性检查。** 以后改代码先看这一列。
